# Verification Plan

**Project:** Coverage-driven verification of FreeRTOS concurrency hazards using UVM-SystemC and a simulated HAL
**Context:** SoC Specialization — University of València (UV)

---

## 1. Purpose and scope

This plan defines *what* is verified, *how success is judged*, and *what evidence
is produced*. The goal is to expose, reproducibly, the classic concurrency
hazards of shared-state embedded firmware, and to prove that a synchronized
version of the same firmware removes them — while the hardware is not yet
available, by running the real firmware on a simulated HAL under a UVM-SystemC
testbench.

The verification is **comparative**: two functionally identical firmware builds
run under the same testbench.

- **Group A (vulnerable):** shared globals accessed with no synchronization.
- **Group B (protected):** identical logic guarded by `pthread_mutex`, with the
  hottest shared struct aligned to a cache line.

## 2. Device Under Test (DUT)

An environmental multi-sensor controller (greenhouse): it samples temperature and
humidity, drives ventilation (PWM fan) and irrigation (GPIO pump relay), raises
alarms (LED), and accepts remote UART commands. The firmware is portable C run on
POSIX threads (FreeRTOS-style task model).

### 2.1 Tasks

| Task | Priority | Writes | Reads |
|---|---|---|---|
| `alarm_task` | 4 (highest) | `alarm_state` | temperature, humidity |
| `sensor_task` | 3 | `sensor_data` (temp, humidity) | — (ADC) |
| `control_task` | 2 | `actuators` (fan, pump) | temperature, humidity, target |
| `comm_task` | 1 | `target_temp`, `system_enabled` | UART |
| `logger_task` | 0 (idle+) | — | liveness heartbeat |

### 2.2 Shared state

`sensor_data` (temperature + humidity), `target_temp`, `actuators`
(pump_on, fan_duty), `alarm_state`, `system_enabled`.

- **Group A:** `volatile` globals, no mutex — the read/modify/write and
  multi-field reads are not atomic.
- **Group B:** the same variables guarded by per-group mutexes;
  `sensor_data` uses a 64-byte cache-line-aligned struct.

### 2.3 Control law (reference for the scoreboard)

- Fan duty: from the temperature error vs target, `FAN_TEMP_TOLERANCE = 2 °C`,
  saturating `[0, 100]`.
- Pump: on when humidity `< HUMIDITY_MIN_LIMIT (30%)`.
- Alarm LED: on when `temp ≥ 35 °C` (alarm) or `≥ 40 °C` (critical), or humidity
  outside `[30%, 70%]`.

## 3. Hazards targeted

| # | Hazard | Where it lives | How it is judged |
|---|---|---|---|
| H1 | Race condition / **torn read** | `control_task` reads unprotected `sensor_data` | Direct coherence check: was the (temp, humidity) pair ever produced together in one real sensor reading? |
| H2 | **False sharing** | adjacent hot globals on one cache line | Isolated microbenchmark (padded vs packed) |
| H3 | **Deadlock / stall** | mutex ordering (Group B) / hung task | Heartbeat watchdog over all 5 tasks (sim-time keyed) |
| H4 | **Priority inversion** | mutex held by low-priority task | Mutex-wait instrumentation + checker |

H1, H3, H4 are checked live by the testbench scoreboard/checkers. H2 is quantified
by an isolated microbenchmark (the effect is real but is dominated by sleep/I/O
time in the full DUT, so it is measured in isolation — see the methodology).

## 4. Verification strategy (Coverage-Driven Verification)

1. **Stimulus:** UVM sequences drive sensor values (with variance so real torn
   reads can arise), UART target commands, and priority-inversion scenarios.
2. **Observation:** passive monitors bridge every HAL operation into UVM
   transactions via a thread-safe queue.
3. **Checking:** a scoreboard with a reference model recomputes expected actuator
   outputs; a direct coherence check detects torn reads at the input; dedicated
   checkers cover data ranges, timing, priority inversion, and deadlock.
4. **Coverage:** functional bins (temperature range × priority × task) plus
   critical-corner counting.
5. **Statistics:** because the tasks are real threads, OS scheduling makes each
   run an independent sample; the stress harness repeats runs to build a
   distribution.

## 5. Tests

| Test | Group | Purpose |
|---|---|---|
| `race_condition_test` | A | Expose torn reads / races |
| `protected_test` | B | Confirm the mutex removes them |
| `priority_inversion_test` | A | Reproduce priority inversion (tasks pinned to one core) |

## 6. Success criteria

- **Functional correctness (H1):** Group A shows a non-zero torn-read rate;
  Group B shows **0 torn reads** across the stress campaign.
- **Liveness (H3):** neither group reports a deadlock; the detector tracks all
  5 tasks and distinguishes normal completion from a stall.
- **Performance (H2, mutex cost):** the isolated benchmarks produce a defensible
  quantitative figure for false sharing and mutex overhead.
- **Reproducibility:** all results regenerated by `make stress && make collect &&
  make plots` and `make bench`.

## 7. Deliverables

- Firmware (Group A, Group B) + simulated HAL.
- UVM-SystemC testbench (agents, scoreboard, checkers, coverage, sequences, tests).
- Automation: stress harness, results aggregation, SVG plots, microbenchmarks.
- Documents: this plan, [methodology](methodology.md), [defect log](defect_log.md),
  and the [final report](report/final_report.md).

## 8. Environment

- Host: 4-core x86-64, cache line 64 B (matches `CACHE_LINE_SIZE`).
- SystemC 3.0.x + UVM-SystemC 1.0-beta; GCC, C17 / C++17.
- `LOOPS_PER_TASK = 10000` per task per run.
